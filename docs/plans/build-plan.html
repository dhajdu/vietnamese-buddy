1Product principle

The app has no curriculum. The learner's day is the curriculum.

Every other Vietnamese app teaches a fixed sequence: greetings, numbers, colours, family. This one asks one question each morning, what situation do you want to practice today?, and generates a lesson for exactly that. The order of topics is whatever life in Saigon throws at the learner: a Grab driver, a date, an internship conversation, ordering bún thịt nướng.

The long-term value comes from the second half: every phrase and word from those disconnected days lands in one persistent vocabulary store with a status, a streak keeps the habit alive, and flashcards turn today's lesson into tomorrow's recall. Disconnected situations become cumulative learning.

Language stance

Southern, spoken, current. coi phim over xem phim. hông explained next to không. Particles (nha, ha, nè, đó, vậy) taught as social meaning, not grammar trivia. anh / em used when the situation calls for it. If the AI output reads like a textbook, the prompt is wrong, not the learner.

2The core loop

Everything in the MVP exists to make these eight steps work end to end, every day.

  1. Enter a situationPlain English, one text box. "I'm asking a coworker to dinner after work."
  2. Generate the lessonServer-side call to the model with a strict JSON schema. Validated with Zod before anything is saved.
  3. Save the lessonFull JSON stored in lessons.lesson_json, with title, situation, and grammar topic denormalised for lists.
  4. Extract and dedupe vocabularyEach vocabulary item is normalised and upserted into the user's vocabulary table. Duplicates link to the existing row.
  5. Create flashcardsTwo decks per lesson: phrase cards and vocabulary cards. Vocabulary cards for already-known words are skipped.
  6. Review cardsFlip, Know it, Review again, Next. Each answer updates card status and the vocabulary row it points to.
  7. Update progressToday's daily_activity row is upserted. Streak is recomputed from activity dates in Asia/Ho_Chi_Minh.
  8. Come back tomorrowHome shows the streak, vocabulary count, today's review count, and recent lessons. Repeat.

Phases 1 to 3 in section 11 build nothing outside this loop. The product should feel useful after the first lesson and the first review.

6Lesson generation

One server function, one schema, no client-side keys.

System prompt

The spec's prompt is used verbatim as the core. Three guardrails are appended, each fixing a failure mode observed in first drafts of this kind of prompt:

  • Counts are hard. 10 to 15 phrases, 12 to 20 vocabulary items, 3 to 5 grammar examples. The schema enforces them and the prompt states them so the model doesn't argue with the validator.
  • Grammar exclusion list. The "avoid" list (chưa / rồi, negation, word order) and the "prefer" list (vừa… vừa…, hay là, để, nếu… thì, càng… càng, chắc, từng, mới, particles, classifiers, topic-comment, subject dropping) go in the prompt as-is. Optionally pass the learner's last five grammar topics so the model avoids repeats.
  • Vocabulary must come from the phrases. Every vocabulary item should appear in at least one phrase or example. This is stated in the prompt and spot-checked in validation (soft warning, not rejection).

Schema

const Phrase = z.object({
  vietnamese: z.string().min(1),
  english: z.string().min(1),
  explanation: z.string().min(20),
});
const Vocab = z.object({ vietnamese: z.string().min(1), english: z.string().min(1) });
const Example = Phrase;

export const LessonSchema = z.object({
  title: z.string().min(3).max(80),
  situation: z.string().min(3),
  phrases: z.array(Phrase).min(10).max(15),
  vocabulary: z.array(Vocab).min(12).max(20),
  grammar: z.object({
    title: z.string().min(3),
    pattern: z.string().min(2),
    explanation: z.string().min(40),
    examples: z.array(Example).min(3).max(5),
  }),
});
export type Lesson = z.infer<typeof LessonSchema>;

generateLesson(situation, options)

  1. Reject empty or >500 char input. Trim.
  2. Call generateObject with the schema, temperature: 0.7, and a 60s abort.
  3. Run LessonSchema.safeParse again on the result (belt and braces: some providers return near-misses).
  4. Post-checks: dedupe vocabulary within the lesson by normalized form; strip trailing punctuation from vocabulary; ensure situation echoes the input.
  5. On validation failure, retry once with the Zod error message appended to the user turn. On second failure, surface a plain error: "The lesson came back malformed. Try again or rephrase the situation."
  6. Return the typed Lesson. The action, not this function, writes to the database.

createLesson action

Wraps the above in one transaction-shaped sequence: insert lesson, upsert vocabulary, insert join rows, insert flashcards, record activity, revalidate / and /lessons, redirect to the lesson. If a later step fails the lesson is deleted so the learner never sees a half-built one.

Regenerate and modify

From a lesson page: "Regenerate" reruns with the same situation, "Adjust" opens a small textarea for a tweak ("make it more casual", "focus on the payment part"). Both create a new lesson row with parent_lesson_id set. The history page shows variants nested under the original.

7Vocabulary and flashcards

Normalisation

Vietnamese dedupe fails on trivial differences: Coi phim vs coi phim, composed vs decomposed diacritics, a trailing "?" the model left on. The key is:

export function normalizeVietnamese(s: string) {
  return s
    .normalize("NFC")                // one codepoint form for ế, ờ, ậ…
    .toLowerCase()
    .replace(/[.,!?;:"'()\[\]…]+$/g, "") // trailing punctuation
    .replace(/^[.,!?;:"'()\[\]…]+/g, "")
    .replace(/\s+/g, " ")
    .trim();
}

Diacritics are kept. ma, má, mà and mã are different words and must stay different rows. Parenthetical glosses the model sometimes adds ("hông (Southern)") are stripped by a pre-pass that removes bracketed suffixes before normalising.

Upsert

For each vocabulary item: compute normalized, insert … on conflict (user_id, normalized) do nothing returning id, fall back to a select on conflict, then insert the join row. New rows get status = 'new'. Existing rows are untouched, so a word the learner already marked known stays known. The action returns the count of genuinely new words for the "new vocabulary" figure on the history page.

Flashcard creation

  • One phrase card per phrase. Back: english + explanation.
  • One vocabulary card per vocabulary row that was newly created or whose status is not known. Known words don't get re-carded.
  • Cards start as new.

Review session

Deck picker: "This lesson", "All due", per-lesson. A session loads cards ordered review first, then new, then known last. The four controls map to:

ControlCardLinked vocabulary
FlipClient-side only
Know itstatus = known, count +1, reviewed nowstatus = known, count +1, reviewed now
Review againstatus = review, count +1status = learning, count +1
Next cardNo change, moves on

Every "Know it" or "Review again" increments daily_activity.cards_reviewed. "Today's review count" on Home is the number of cards with status review plus cards with status new from lessons created before today, capped for display.

Vocabulary page

Server-rendered list with a search box (matches on vietnamese and english, case-insensitive, diacritic-sensitive), a status filter (All · New · Learning · Known), and a column showing the introducing lesson as a link. A three-state toggle on each row sets status directly. The header shows the running counter: Vocabulary learned: 187 words where "learned" means introduced, with a smaller "132 known" beside it.

8Streak and activity

Local date first, everything else follows:

export function localDate(tz = "Asia/Ho_Chi_Minh", now = new Date()) {
  return new Intl.DateTimeFormat("en-CA", { timeZone: tz,
    year: "numeric", month: "2-digit", day: "2-digit" }).format(now); // "2026-09-10"
}

recordActivity(kind) upserts today's row and sets the relevant column. computeStreak(dates) takes the user's distinct active dates descending and walks back from today (or yesterday, so an unbroken streak doesn't show 0 before the learner has done anything today). Longest streak is the longest consecutive run over all dates. Total learning days is the row count. All three are computed on request; the table is small.

The 30-day calendar on Progress is a 5×6 grid of local dates, each cell shaded by whether the day had activity, with a tooltip listing what happened.

10Design system

Clean, adult, and quiet. Vietnamese is the hero; English is the caption.

Tokens live in app/globals.css as CSS variables and are exposed to Tailwind through @theme. Nothing in components uses a raw hex.

Type

  • Be Vietnam Pro for headings, Vietnamese text, and UI. Designed for Vietnamese diacritics, so ậ ễ ờ render at the right height instead of colliding.
  • Newsreader for English body and explanations. Serif keeps the English visibly secondary.
  • JetBrains Mono for the grammar pattern line only.
  • Scale: 13 · 15 · 17 · 20 · 24 · 30 · 40. Vietnamese in a phrase row is 20, English is 15, explanation is 15 in ink-2.

Layout and components

  • Content max width 720px. Generous vertical rhythm on an 8px grid.
  • Lesson sections are the only cards: 1px line, 8px radius, no shadow.
  • Stat tiles: number in Be Vietnam Pro 600 with tabular-nums, label in 13px uppercase, letter-spaced.
  • Flashcard: one centred surface, 3:2 ratio, flip on click and Space. Back shows English in serif, explanation below a hairline.
  • Progress: a thin bar, not a ring. The 30-day calendar uses accent at 100% for active days and line colour for empty.
  • Dark theme from the same tokens. No emoji as section markers; the 🔥 in the streak is the one exception and it is a real product convention.

13Acceptance criteria

  • A new user can log in by email, create a lesson from a plain-English situation, and see it saved in under 30 seconds.
  • Every generated lesson has 10 to 15 phrases, 12 to 20 vocabulary items, and one grammar section with 3 to 5 examples. Anything else is rejected before saving.
  • Creating two lessons that share words produces no duplicate vocabulary rows for that user.
  • "Know it" on a vocabulary card marks the vocabulary row known and it disappears from future decks.
  • Streak increments once per local day regardless of how many lessons or reviews happen, and survives a review at 23:55 ICT followed by one at 00:05 ICT as two days.
  • Regenerating a lesson leaves the original intact and reachable from History.
  • No AI key or service-role key is ever sent to the browser. Verified by grepping the client bundle.
  • The app is readable and operable on a 375px phone and in dark mode.

14Risks and decisions

RiskMitigation
Model drifts to Northern or textbook VietnamesePrompt states Southern explicitly with examples. Add a "sounds textbook" flag on the lesson page that records feedback for prompt tuning later.
Generation cost and latencyRate limit per user per day. Stream nothing; a single structured call is simpler and the wait is acceptable once a day.
Vocabulary dedupe misses variants (đi ăn vs đi ăn tối)Accept it. Only exact normalised matches dedupe. Anything smarter is spaced-repetition territory and out of scope.
Streak logic disagrees with the learner's sense of "today"Timezone stored per user, default ICT, editable later. All date maths server-side from one helper.
Magic-link deliverabilitySupabase default sender is fine for one user. Custom SMTP is a Phase 5 concern.

Decisions taken in this plan

  • Vercel AI SDK over the raw OpenAI client, OpenAI as the default provider.
  • Streak computed on read, not stored.
  • Regenerations are new rows with a parent pointer, never edits.
  • Vocabulary dedupe keeps diacritics and only normalises case, Unicode form, whitespace, and edge punctuation.
  • Cards for already-known words are not created.

15Not in the MVP

Named so they don't creep in:

  • Spaced repetition scheduling (SM-2 or similar). The four-button review is enough for now.
  • Audio, text-to-speech, or pronunciation scoring.
  • Social features, leaderboards, achievements, badges.
  • Multiple login providers. The auth layer allows it; nothing is wired.
  • Multi-language or Northern dialect toggle.
  • Editing a lesson's phrases by hand.
  • Push or email reminders for the streak.
